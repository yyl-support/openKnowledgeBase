# 图片标签提取与增强机制

## 定义

[[ForumBot]] 在论坛文本处理管线中对图片标签进行提取与增强的机制：用正则从文本中提取 `[img: (...)]` 标签，将相对路径解析为绝对 URL，调用 [[多模态模型服务]] 生成技术内容描述，最终把标签替换为 `[图片: 描述]`；用户头像图片标签则直接删除。该机制的实际实现者是 [[ImageProcessor]]。

## 流程

1. **提取标签**：用正则 `\[img: \((.*?)\)\]` 匹配所有图片标签。
2. **解析 URL**：`http` 开头视为绝对路径；否则基于基准 URL（默认 [[OpenUBMC 论坛]]）用 `urljoin` 解析。
3. **头像判定**：URL 含 `user_avatar` 时返回 `USER_AVATAR`，最终直接删除标签。
4. **提示词选择**：根据 `context` 关键词切换提示词（见下文）。
5. **模型调用**：按 `model1 → model2 → model3` 顺序故障转移调用 [[多模态模型服务]]。
6. **替换/删除**：普通图片替换为 `[图片: 描述]`，头像标签删除；可选按 `topic_id` 记录 token 用量到 [[token_tracker]]。

## 上下文相关提示词策略

根据 `context` 关键词切换提示词，体现 [[ForumBot]] 问答数据流不同环节对图片信息的不同需求：

| context 关键词 | 提示词目标 |
| --- | --- |
| `user_question` | 逐字提取截图中的文字信息（错误日志、配置界面、代码片段），不加总结或推测 |
| `best_answer` | 总结截图中的关键技术信息（解决方案截图、配置示例、日志分析） |
| 默认 | 描述图片内容，重点关注技术信息和关键细节 |

## 多模态模型故障转移策略

- 按 `model1 → model2 → model3` 顺序调用 [[多模态模型服务]]。
- 单个模型失败时记录错误日志并切换下一个模型。
- 全部模型失败才抛出异常，由上层 `process_image_content` 捕获并返回「图像内容分析失败」兜底文案。

## 意义

- 让下游步骤能理解图片内容，避免错误日志、配置、代码截图等关键技术信息在文本处理中丢失。
- 头像图片直接删除，避免无关噪声进入处理管线。
- 配合 [[token_tracker]] 按主题记录模型调用开销，支撑成本统计。
