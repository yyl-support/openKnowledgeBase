# 数据处理与持久化模型

## 定义

[[data_processor]] 采用「数据库 + 文件」双写的持久化模型：处理结果同时写入 PostgreSQL 关系表与 JSON/CSV 文件。数据库侧保证结构化查询与分析能力，文件侧保留原始结果的快照，便于人工检查与调试。

## 数据表清单

| 表名 | 内容 | 写入方式 |
|---|---|---|
| forum_search_results | 每个 topic 的搜索关键字与结果，结果限量 10 条并拆分为 result_1..result_10 列，不足用 NULL 填充 | INSERT |
| forum_retrieval_results | 每个 topic_id 对应的检索结果（related_docs，JSONB） | INSERT |
| consume_tokens_topic | 每个 topic 的 prompt/completion/total token 与 model_calls | upsert（ON CONFLICT (topic_id) DO UPDATE） |
| evaluation_samples | 每次问答的输入、检索上下文、实际输出、延迟与 token 用量 | INSERT（见 [[评估样本采集]]） |
| forum_topics | 已抓取帖子的 ID 来源表，用于增量去重 | 只读（SELECT id） |
| pre_audit_topics | 预审帖子的 ID 来源表，用于增量去重 | 只读（SELECT id） |

## 关键模式

### 搜索结果限量存储

搜索结果显示的 10 条结果被拆分为 `result_1`..`result_10` 共 10 个列存储（psycopg2 自动将 dict 序列化为 JSONB），同时记录 `total_results` 与 `displayed_results`。

### token 用量 upsert 语义

`save_token_usage_to_db` 以 `topic_id` 为冲突键执行 `ON CONFLICT DO UPDATE`，确保同一 topic 的 token 用量被覆盖更新而非追加。

### 增量去重

通过 `load_existing_data` / `load_pre_audit_existing_data` 将 forum_topics / pre_audit_topics 中已有的 ID 加载为集合，供抓取流程跳过已入库或预审中的帖子。

## 文件落盘

- 搜索结果：`forum_data_dir/search_results_topic_{topic_id}_{timestamp}.json`
- 检索结果：`forum_data_dir/retrieval_results_{timestamp}.json`
- 帖子数据：追加写入 `paths.csv_file` 配置指定的 CSV 文件
